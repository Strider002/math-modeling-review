# 证据与质量门禁

本文件是处理外部证据、竞赛规则、获奖论文、GitHub/外部代码、知识入库或存在来源争议时加载的完整证据门禁；所有正式建模任务常驻的最小红线见[永久质量核心](00Q_永久质量核心.md)。目标不是保证“永不出错”这种无法证明的承诺，而是让每个事实、公式、数据和结论都可追踪、可检查、可推翻。

## 1. 证据等级

| 等级 | 证据 | 可支持的表述 |
|---|---|---|
| A | 官方原题、官方规则、官方数据、标准、原始论文/教材、数据提供方文档 | 可作为定义、规则、数据口径或理论依据 |
| B | 经同行评审论文、权威教材、官方软件文档 | 可作为方法、条件和实现依据 |
| C | 获奖论文全文、公开技术报告、机构讲义 | 可作为案例和候选做法；公式必须另核 |
| D | 博客、课程笔记、论坛、搜索摘要 | 仅作线索，不能单独支撑关键事实 |
| U | 无法定位来源或只凭记忆 | 不得写成事实；必须标“待核验” |

“一等奖/特等奖”是竞赛综合评价，不等于论文内每个公式、参数或结论都正确。

证据等级必须绑定到**具体主张**，不能给整份资料永久贴一个等级。同一官方页面对竞赛结果可以是
A 级，对其展示的学生论文方法仍只提供 C 级案例证据；原始方法论文可支持定义与原始推导，
不自动支持某软件当前版本的实现或新数据上的性能。关键主张按
[00C_知识条目与证据维护规范.md](../来源依据/来源索引.md) 记录来源 ID、精确定位、版本、条件和核验状态。

## 2. 禁止编造

下列信息若原题、数据或可靠来源没有给出，不得自行补齐：

- 样本量、时间范围、单位、缺失率和数据来源；
- 参数值、阈值、权重、概率分布和随机种子；
- 模型性能、显著性、置信区间、提升比例和运行时间；
- 法规、行业标准、设备性能、成本和地理事实；
- “最优”“显著”“准确”“因果”“稳健”等结论。

合理假设必须显式标为假设，并写出依据、作用范围、违反后的影响和敏感性方案。假设不能伪装成已知数据。

## 3. 公式四审

任何进入主模型的公式逐项检查：

1. **定义审**：每个符号、索引、集合、单位和正负方向是否定义；
2. **条件审**：独立、平稳、凸、可微、同分布、非负、可识别等条件是否成立；
3. **量纲审**：等式两边及目标函数各项量纲是否一致；指数和对数的自变量通常应无量纲；
4. **边界审**：零、极端值、常数列、空集、满负荷、无扰动和已知解析小例是否给出合理结果。

实现后再做“公式—代码一致性”审计：索引上下界、归一化分母、正负号、单位换算、目标方向、约束方向必须逐项对应。

## 4. 数据五审

1. **来源**：原始文件、版本、获取时间、哈希；
2. **口径**：对象、时间、空间、单位、币种、时区、修订状态；
3. **结构**：主键、重复、一对多连接、层级、分组和时间顺序；
4. **质量**：缺失机制、测量误差、异常含义、选择偏差、标签噪声；
5. **可用性**：部署/决策时是否真实可得，是否含未来信息。

任何清洗都记录规则、影响行数和可逆性。不得无记录删除异常或用全数据拟合插补、缩放、编码和特征选择。

## 5. 结论强度

证据与措辞必须匹配：

- 描述数据：使用“样本中观察到”；
- 预测验证：使用“在指定划分与指标下”；
- 参数解释：使用“模型条件下相关”；
- 因果结论：只有识别策略和假设成立时使用“干预效应”；
- 优化结论：只有全局最优证据充分时使用“全局最优”，否则写“当前最好可行解”；
- 外推：明确目标总体、时间/空间范围和分布漂移风险。

## 6. 最低证据包

每个重要模型至少保存：

- 原题要求与交付项映射；
- 数据字典、来源和哈希；
- 数学定义、假设和单位；
- 基线与主模型；
- 训练/验证/测试或仿真设计；
- 误差、区间、约束违反量或最优性 gap；
- 一项敏感性和一项压力测试；
- 配置、随机种子、软件/求解器版本；
- 结果表和论文数字的一致性检查。

缺少任一项时，必须在交付中说明，而不是用主观形容词补足。

## 7. 来源冲突

来源冲突时：

1. 优先原始、官方、版本更新且定义清楚的来源；
2. 检查是否对象、时间、单位或统计口径不同；
3. 保留冲突记录，不静默选取更符合预期的数值；
4. 无法消解时给区间/多情景，并说明决策对冲突是否敏感。

## 8. 获奖论文使用规则

只提炼：

- 问题拆解与模型链；
- 可复用的验证设计；
- 图表与摘要表达；
- 值得复查的薄弱环节。

不得直接继承：

- 未给来源的参数；
- 未核验的公式与单位；
- 没有基线的性能结论；
- 把相关写成因果、把启发式写成全局最优的表述；
- 无法运行或与正文不一致的附录代码。

## 9. 第三方全文与 GitHub 的准入门禁

允许从大学或研究机构仓储、作者主页、期刊数据库、GitHub/GitLab 等合法公开渠道发现论文全文、
补充材料和代码，但“可访问”不等于“已证实”。进入正式知识库前必须分别通过以下门禁：

1. **奖项身份门禁**：竞赛名称、年份、题号、队号和奖项只能由对应赛事官方结果页、官方结果 PDF
   或组委会发布材料确认；作者自述、仓库 README、文件名和搜索摘要不能单独证明奖项。
2. **全文真实性门禁**：优先采用作者或学校机构仓储；记录原始 URL、获取时间、页数和 SHA-256。
   若来自个人网站、镜像或代码仓库，至少与官方元数据及一个独立可信来源核对题名、队号、年份、
   题号、作者/学校和文档结构；无法排除错版、删改或冒名时只进入候选台账。
3. **方法正确性门禁**：获奖论文仍为 C 级案例。公式、定理、参数口径和算法性质必须由原始论文、
   权威教材、标准或官方软件文档独立核验，并通过定义、条件、量纲、边界和公式—代码一致性检查。
4. **代码可信性门禁**：GitHub 星标、fork 数、提交活跃度和 README 声明只作线索。记录仓库所有者、
   与论文作者/机构的可验证关系、许可证、固定 commit/tag、依赖版本和文件哈希；不能确认作者关系时，
   代码只作为第三方复现候选，不标为“论文官方代码”。
5. **复现门禁**：运行外部代码前先静态检查入口、依赖、网络访问、文件写入和危险命令；不得提供密钥，
   不执行来源不明的安装脚本或破坏性命令。随后在隔离目录使用最小数据做 smoke test、手算/解析小例、
   边界/不变量检查和多随机种子测试；能取得原始数据时再核对论文表格、图或关键数值。
6. **冲突门禁**：官方身份、全文版本、正文公式、代码实现或复现结果任一冲突无法消解时，保留冲突记录，
   标记“待核验/不可复现”，不得把相关知识写入主专题。

本库不承诺无法证明的“100% 正确”。通过上述门禁后，只能表述为“在已列证据、版本、测试和适用条件下
通过核验”，并继续保留来源等级、局限和剩余不确定性。

### 外部来源访问失败

单一客户端失败不能证明来源整体不可用。可用合法的其他只读访问通道复核；不关闭 TLS 校验、不提供密钥、不执行来源不明的脚本。来源不可访问时明确未核验范围。
