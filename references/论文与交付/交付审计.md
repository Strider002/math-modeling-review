# 任务契约、数字一致性与 PDF 文本审查

用于检查已经声明的题目覆盖、结果引用及交付文本。工具默认只读，不运行用户模型，不训练、不修改论文、不重新冻结结果。运行范围仍以用户授权为准。

## 1. 先区分证据层级

| 检查 | 能确认 | 不能确认 |
|---|---|---|
| 结果清单复核 | 声明文件的路径、大小、哈希及清单结构 | 模型正确、实验有效、论文数字含义 |
| 任务契约审计 | 声明问题有回答标记；绑定数字与固定来源一致；出现次数符合声明 | 问题声明穷尽原题、未绑定正文正确、答案科学有效 |
| PDF 文本审查 | 可提取文字中的已实现引用错误、草稿标记及可选匿名词 | 图中文字、版面、公式语义、引用真实性、完整匿名合规 |
| 人工表达审查 | 在实际阅读范围内检查解释、论证与可读性 | 未执行的独立读者反馈或官方评分结果 |

学习或调参任务必须保留训练/校准外评价；纯确定性任务使用独立真值、解析边界或匹配情景核验。不要为了填写清单虚构训练集、随机种子、重复试验或误差条。

## 2. 显式运行只读审计

下面路径由当前 Skill 和用户项目解析。Python 工具要求 Python 3.10 或更高版本；不自动安装依赖。

```powershell
python -B "$SkillRoot/scripts/audit_contract.py" --project-root "$ProjectRoot" --stage paper --contract task-contract.json
python -B "$SkillRoot/scripts/pdf_text_audit.py" "$ProjectRoot/paper/solution.pdf"
& "$SkillRoot/scripts/verify_results.ps1" -ProjectRoot $ProjectRoot
```

这些新工具在公开包中作为独立检查使用，不声称已经自动接入旧版 `modeling_stage.ps1` 或 `build_submission.ps1`。需要阶段化项目时，在使用者授权的流程中显式安排检查；不能把旧工具的通过状态替代新检查。

契约工具只使用 Python 标准库。PDF 工具先尝试本机已有的 pypdf，再尝试 pdftotext；可用 `--extractor pypdf` 或 `--extractor pdftotext` 指定。提取器缺失、空白/扫描页或已识别的编码异常返回 `UNVERIFIED`，不是通过；不得据此声称交付文本已完成审查。

契约没有声明时可能返回 `LEGACY_UNCHECKED` 且进程退出码为 0。自动流程必须同时检查输出状态，不能仅看退出码。显式传入 `--contract` 时文件缺失即失败。PDF 退出码分别为 0（文本检查通过）、1（发现问题）、2（检查未完成）。

## 3. 契约怎样声明

所有文件路径相对用户项目根目录，使用 `/`，不接受绝对路径、父目录跳转、符号链接或 Windows 联接。契约只扫描声明的 Markdown/TXT，不扫描 PDF 或图像。

| 顶层字段 | 作用 |
|---|---|
| `schema_version` | 固定为字符串 `1.0.0` |
| `questions` | 非空列表；每问声明 `id`、`prompt`、`answer_file`、`answer_marker`、`required_result_keys`、`from_stage` |
| `required_artifacts` | 每项声明 `path`、`from_stage` |
| `results` | 每个结果键绑定一个固定来源与显示格式 |
| `documents` | 非空列表；每份声明 `path`、`from_stage`，建议明确 `result_occurrences` |

`from_stage` 可为 `problem`、`data`、`model_selection`、`implementation`、`validation`、`paper`、`submission`。未来阶段产物尚未到期不等于已验证；以 `complete` 审计时覆盖全部已声明阶段。

每个结果项需要 `key`、`source_file`、`pointer`、`format`、`unit`、`scope`、`run_id_pointer`、`run_id`、`source_sha256`、`from_stage`。来源为 JSON，定位采用 JSON Pointer；显示格式可为 `integer`、`fixed:0` 至 `fixed:12`、`json` 或 `string`。`identity_guards` 可增加输入版本等相等性检查。数值来源为 Excel/CSV 时保留原主源，仅在授权下生成可追溯的只读导出，不手工维护第二套数值。

在文本中显式绑定答案及结果，以下仅为语法示意，不是实验结果：

```text
<!-- answer:Q1 -->
写明该问的回答、比较条件与验证边界。
结果为 <!-- result:metric.value -->实际来源对应的显示值<!-- /result:metric.value -->。
<!-- /answer:Q1 -->
```

`documents[].result_occurrences` 按文档记录每个键的预期出现次数；这样删除绑定标记不能静默缩小检查范围。工具仍无法识别没有声明过的数字，审阅者须另行核对原题、正文与图表。

## 4. 英文、公式与图表验收

- 遮住正文检查 Summary 是否仍交代任务、方法理由、关键发现、比较对象和有条件的建议；数字回到同一结果键。
- 公式前说明现实关系，公式后说明变量、单位、主要项、假设及边界。不要仅把符号翻译一遍。
- 每张图先指定问题和核心信息，再安排坐标、单位、分组、区间、图注及正文用途。最终尺寸实际渲染后才记录视觉验收。
- 检查增强模块的增量价值；未重跑的删减分析只称逻辑审查，不称消融试验。删减实现不能丢掉题目要求、硬约束或验证证据。
- 自审、代理交叉审查、人类独立阅读和盲评分开记录。赛前/赛后可安排外部阅读训练；正式竞赛按当届规则执行。
