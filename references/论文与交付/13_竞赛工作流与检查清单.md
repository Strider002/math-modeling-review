# 竞赛工作流与检查清单

## 1. 读题阶段

- 圈出对象、动词、限制词、时间空间范围；
- 将每问改写为“输入—输出—评价标准”；
- 标出子问题依赖；
- 列出必须交付的表、图、预测、排序、方案或建议；
- 检查附件字段、单位、缺失、口径和可用时间；
- 识别隐含约束和现实常识；
- 为每问选一个基线与 1–2 个候选模型。

产出：问题树、数据清单、模型链草图。

## 2. 第一版闭环

先在最短时间内完成：

1. 数据能读；
2. 有基本 EDA；
3. 每问有可运行基线；
4. 有初步结果；
5. 有至少一项验证；
6. 论文骨架和结果占位图已建立。

闭环后再升级，避免模型做得很深但题目没有答全。

## 3. 数据阶段

- [ ] 数据字典
- [ ] 主键/重复
- [ ] 类型和单位
- [ ] 缺失机制
- [ ] 异常含义
- [ ] 时间顺序
- [ ] 空间坐标
- [ ] 标签泄漏
- [ ] 划分方案
- [ ] 清洗日志

## 4. 模型阶段

- [ ] 目标函数或评价指标与题意一致
- [ ] 决策/状态/外生变量区分
- [ ] 假设必要且可检验
- [ ] 有基线
- [ ] 参数来源明确
- [ ] 复杂度与数据量匹配
- [ ] 子模型输入输出衔接
- [ ] 单位一致
- [ ] 代码和数学表达一致
- [ ] 随机种子和求解设置记录

## 5. 验证阶段

- [ ] 训练外/历史/外部验证
- [ ] 残差或误差分布
- [ ] 分组误差
- [ ] 与基线比较
- [ ] 极端边界测试
- [ ] 敏感性
- [ ] 情景分析
- [ ] 约束违反量
- [ ] 多种子/多初值
- [ ] 不确定区间

## 6. 论文阶段

- [ ] 摘要有数字
- [ ] 每问都有明确结论
- [ ] 问题分析解释模型链
- [ ] 假设有依据
- [ ] 符号与单位统一
- [ ] 公式后有现实解释
- [ ] 图表可独立理解
- [ ] 结果有验证与局限
- [ ] 建议具体可执行
- [ ] 参考文献和数据源完整
- [ ] 附录代码可复现

## 7. 时间有限时的优先级

1. 答全题目；
2. 数据和公式正确；
3. 有基线与验证；
4. 结论清楚；
5. 敏感性与稳健性；
6. 提升模型；
7. 美化。

## 8. 子问题衔接

当模型链为“预测 → 优化 → 评价”：

- 预测阶段输出点估计和区间/情景；
- 优化阶段对多个预测情景求解或评估；
- 评价阶段比较成本、服务、风险和稳健性；
- 不确定性要贯穿全链条；
- 最终建议说明何时切换方案。

## 9. 最终自问

- 如果删掉模型名，读者是否仍看得懂逻辑？
- 如果数据改变 5%–10%，建议会不会翻转？
- 模型是否利用了任何部署时不可得的信息？
- 复杂模型比简单基线多带来了什么？
- 哪条假设一旦失效，结论最危险？
- 决策者看完后知道要做什么吗？

## 10. 赛后沉淀

提交后立即：

1. 保存最终数据、代码、参数和结果；
2. 区分最终版和废弃尝试；
3. 用 扩展专题（未随包提供）：建模复盘模板.md 复盘；
4. 把新方法补到对应专题；
5. 在 扩展专题（未随包提供）：CHANGELOG.md 登记；
6. 对可复用代码写最小示例和输入输出说明。

### 10.1 终稿冻结与停止优化

进入编码前先冻结任务契约：估计对象、数据口径、候选模型、外层验证、主指标、敏感性范围、跨模块接口和失败后的降级路线。之后的新意见分为三类：

1. **正确性阻塞：** 泄漏、公式—代码不一致、约束违反、题目漏答或数字冲突，必须修；
2. **证据增强：** 额外模型、Bootstrap、情景或审计，只有能改变模型选择、结论强度或决策时才进入主流程；
3. **表达改进：** 图表、措辞和排版，不得借机改变已冻结的模型与结果。

终稿应使用一个规范工作区、一个当前 `run_id` 和一份产物清单，不使用多个带编号目录表示“最新版”。每个论文数值映射到唯一结果键；验证不仅检查正确值是否出现，还要检查同一结果键是否在摘要、正文、结论和图表中出现冲突值。

当全题闭环、训练外验证、主要不变量、预先定义的敏感性、数字追溯和题目覆盖均通过，且新增复杂度不再改变结论时，应停止扩模并把剩余风险写入局限。若连续三轮所谓“最后修改”仍在不同位置暴露新问题，先检查单一事实源、版本目录和自动生成链，不继续叠加局部门禁。

## 11. 2026 年 AI 工具使用提交检查

自 2026-09-01 起，参加国赛时逐项检查：

- [ ] 无论是否使用 AI，已在论文参考文献之前放置对应的“AI工具使用声明”
- [ ] 未使用时采用官方声明：“本参赛队在竞赛过程中未使用任何AI工具。”
- [ ] 使用时采用官方句式并如实替换简要用途：“本参赛队在竞赛过程中使用了AI工具，主要用于
  〖简要用途，如语言润色、代码调试等〗，详细使用情况见支撑材料。”
- [ ] 声明与实际使用情况一致；不能把代码补全、调试、分析或智能体调用漏记为“未使用”
- [ ] 若使用 AI，支撑材料含文件名完全为 `AI工具使用详情.pdf` 的说明文件
- [ ] 详情写明工具名称、版本/型号、用途与环节、主要提示方式和使用过程
- [ ] 除纯语言润色外，详情写明输出如何被采纳、人工修改以及用什么证据核验
- [ ] 核心建模与分析由参赛队主导，AI 生成的公式、代码、数据解释和结论已逐项人工复核
- [ ] 论文、代码、详情说明和实验日志能互相对应，没有虚假声明或隐瞒

官方规则允许使用 AI，但不要求使用；隐瞒、虚假声明，或直接提交未经必要人工审查与核实的
AI 核心成果，可能直接导致取消评奖资格。其他不符合规定的作品也属于违反竞赛规则并按情节处理。
2026-09-01 起如旧规定与本规定冲突，以本规定为准，解释权属于全国组委会。可用
[AI 工具使用详情模板](../../assets/模板/AI工具使用详情模板.md) 整理真实过程，但该模板不是官方固定表格。

证据绑定：`source:CUMCM-AI-RULE-2026`。

## 12. 优秀论文对照

完成第一版闭环后，用 扩展专题（未随包提供）：20_国赛优秀论文方法论.md 对照：

- 摘要是否逐问给出方法和数值；
- 子问题是否真正递进；
- 每个方法在模型链中是否必要；
- 验证是否匹配题型；
- 元启发式和机器学习是否有基线；
- 预测不确定性是否传入决策；
- 相关性是否被误写成因果、替代或互补。
